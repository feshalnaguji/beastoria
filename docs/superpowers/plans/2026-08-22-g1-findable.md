# G1 "Findable" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Beastoria a real discovery surface — full SEO head tags, 13 static content pages (guide landing + 12 species + privacy), sitemap/robots, a code-crafted icon set + OG share image, and a PWA manifest — with zero sim code changes.

**Architecture:** All URL-bearing output derives from one config module (`src/content/site.ts`). A local Vite plugin (imported by `vite.config.ts`, which esbuild-bundles TS imports natively — no new build tooling) emits the static pages, `sitemap.xml`, and `robots.txt` into `dist/` at build time and injects canonical/OG-URL/JSON-LD tags into `index.html`'s head. Page HTML comes from pure template functions in `src/content/`, unit-tested at the string level. Icons/OG image are rasterized once from committed master SVGs by a plain-Node script and the PNG outputs are committed, so `npm run build` and CI never grow new dependencies.

**Tech Stack:** TypeScript, Vite 6 (existing), Vitest (existing), `sharp` + `png-to-ico` as devDependencies for the one-time icon script only.

**Spec:** `docs/superpowers/specs/2026-08-22-growth-distribution-design.md` (read it first — it carries the binding user decisions).

## Global Constraints

- **Zero cost, ever:** MIT/OSS only. New packages allowed: `sharp`, `png-to-ico` — devDependencies only, used only by the manually-run icon script, never by `npm run build` or CI.
- **No sim changes:** nothing under `src/sim/`, `src/render/`, `src/rigs/`, `src/audio/`, `src/persist/`, `src/app/`, `src/ui/` is touched. The existing 238 tests must pass unmodified.
- **Domain portability:** the canonical base URL `https://feshalnaguji.github.io/beastoria/` appears in exactly ONE committed source location: `src/content/site.ts`. Every absolute URL (canonical tag, og:url, og:image, sitemap, robots' Sitemap line, JSON-LD) is derived from it at build time. (Exception: `package.json` `homepage` — npm metadata can't import TS; a comment in `site.ts` notes it.)
- **Child-directed posture:** no trackers, no analytics, no external scripts/fonts/CDNs on any page. Pages are pure HTML/CSS, zero JS.
- **Art:** 100% code-crafted SVG. No AI images, no asset packs, no downloaded artwork.
- **Attribution:** species pages must credit audio sources per `public/audio/LICENSES.md` — CC-BY/CC-BY-SA entries need author + license + source link on-page.
- **Honest copy:** kid-facing, warm, short, factual. No keyword stuffing, no "no ads" promises (ads are planned later).
- Node 22 (CI), Windows dev machine. `npm run build` = `tsc && vite build`; deploy workflow uploads `dist/`.

}

/** Wrap a page body in the shared shell. canonicalPath is relative to baseUrl, e.g. 'guide/rabbit/'. */
function shell(opts: { title: string; description: string; canonicalPath: string; body: string }): string {
  const canonical = `${SITE.baseUrl}${opts.canonicalPath}`;
  return `<!doctype html>
<html lang="en">
<head>
<meta charset="UTF-8" />
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
<title>${opts.title}</title>
<meta name="description" content="${opts.description}" />
<link rel="canonical" href="${canonical}" />
<link rel="icon" href="${relRoot(opts.canonicalPath)}favicon.svg" type="image/svg+xml" />
<meta property="og:title" content="${opts.title}" />
<meta property="og:description" content="${opts.description}" />
<meta property="og:url" content="${canonical}" />
<meta property="og:image" content="${SITE.baseUrl}og-image.png" />
<meta property="og:type" content="website" />
<meta property="og:site_name" content="${SITE.name}" />
<meta name="twitter:card" content="summary_large_image" />
<meta name="theme-color" content="${SITE.themeColor}" />
<style>${CSS}</style>
</head>
<body><main>${opts.body}</main></body>
</html>`;
}

/** '../' segments to reach site root from a canonical path like 'guide/rabbit/'. */
function relRoot(canonicalPath: string): string {
  const depth = canonicalPath.split('/').filter(Boolean).length;
  return '../'.repeat(depth);
}

- [ ] **Step 1: Write the plugin**

```ts
import type { Plugin } from 'vite';
import { GUIDE } from '../src/content/guide';
import {
  headInjectionTags, renderGuideIndex, renderPrivacyPage,
  renderRobotsTxt, renderSitemapXml, renderSpeciesPage,
} from '../src/content/pageTemplates';

/** All generated static files, keyed by output path. */
function generatedFiles(): Map<string, string> {
  const files = new Map<string, string>();
  files.set('guide/index.html', renderGuideIndex());
  for (const entry of GUIDE) files.set(`guide/${entry.id}/index.html`, renderSpeciesPage(entry));
  files.set('privacy/index.html', renderPrivacyPage());
  files.set('sitemap.xml', renderSitemapXml());
  files.set('robots.txt', renderRobotsTxt());
  return files;
}

export function sitePages(): Plugin {
  return {
    name: 'beastoria:site-pages',
    transformIndexHtml() {
      return headInjectionTags();
    },
    generateBundle() {
      for (const [fileName, source] of generatedFiles()) {
        this.emitFile({ type: 'asset', fileName, source });
      }
    },
    configureServer(server) {
      // Serve the generated pages during `npm run dev` so styling is iterable.
      server.middlewares.use((req, res, next) => {
        const url = (req.url ?? '').split('?')[0] ?? '';
        const path = url.replace(/^\//, '').replace(/\/$/, '/');
        const file = generatedFiles().get(
          path.endsWith('/') || path === '' ? `${path}index.html` : path,
        );
        if (file === undefined) return next();
        res.setHeader(
          'Content-Type',
          path.endsWith('.xml') ? 'application/xml'
            : path.endsWith('.txt') ? 'text/plain'
            : 'text/html',
        );
        res.end(file);
      });
    },
  };
}
```

Note: `transformIndexHtml` returning tag descriptors makes Vite inject them into `<head>`; the JSON-LD script gets `injectTo: 'head'` from Task 3's descriptors. Dev-server note: only `/guide/…`, `/privacy/`, `/sitemap.xml`, `/robots.txt` match the map; everything else falls through to Vite.
