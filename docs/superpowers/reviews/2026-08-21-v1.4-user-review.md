# v1.4 user review — 2026-08-21 (drives M13)

User feedback after the v1.4 live review, on the deployed site (verbatim themes):

1. **Mammals shown "warming the eggs"** — mammal parents (rabbit/deer/squirrel/kangaroo — all
   live-birth) are labeled as tending eggs during the pre-birth wait, which is wrong; only birds
   and fish should ever be shown with eggs.
2. **Mammals should nurse, not just avoid the egg label** — "animals should feed their baby milk
   right? like how their real life behaviour works" — the fix should follow each species' actual
   real-world reproductive/feeding behavior, not just remove the wrong word.
3. **Kangaroo joey mounting reads as magic** — "kangaroo baby comes near mother and then magically
   goes into pocket" — no visible transition, it just appears inside.
4. **Feeding is still generic across species** — "feeding still need to be improved properly
   according to that particular creature's real life way and not just some random same way for
   all" — explicitly wants per-species real-world-behavior fidelity, not one shared mechanism with
   parameter tweaks.

## Root causes (from code investigation, 2026-08-21)

- **Item 1, confirmed exact:** `src/ui/InspectCard.ts:124-125` — the `'brood'` activity case
  unconditionally returns `'keeping the eggs warm'` with no branch on `reproduction.mode`.
  `src/sim/family.ts:424-429` confirms the sim itself reuses the *same* `'brood'` activity id for
  BOTH egg-sitting (`mode: 'egg'`) and live-birth gestation (`mode: 'live'`) — there is no
  sim-level distinction between "sitting on eggs" and "pregnant," so the UI's blanket text was
  always going to be wrong for one half of the species roster. Confirmed live-birth species (via
  `src/sim/species.ts`): rabbit, deer, squirrel, kangaroo. Confirmed egg species: robin, duck, owl,
  dodo, phoenix (birds), koi, frog, turtle (fish/amphibian).
- **Item 2, partially built already, needs verification not fresh design:** `feedMode: 'nurse'` on
  SpeciesParams (`species.ts`) already exists for exactly the four live-birth mammals and already
  drives real "mother nurses at home, babies gather to her" behavior (`family.ts`/`behaviors.ts`,
  built across M10-M12). It's unclear from the user's message whether milk-feeding isn't
  *happening*, isn't *reading clearly as milk* (vs. some other feeding cue), or whether item 1's
  wrong "eggs" label is what made it look like mammals weren't following mammal behavior at all —
  these are plausibly the same underlying confusion. Needs a fresh live-review pass once item 1 is
  fixed, before assuming nursing itself needs redesign.
- **Item 3, confirmed exact:** `src/sim/family.ts:171-172` — `stepPouch`'s mount condition is a
  hard binary flip: the instant a joey's distance to its mother is `<= MOUNT_RANGE` (60 units),
  `joey.carriedBy = mother.id` fires with no intermediate state. On the render side
  (`src/render/Renderer.ts`'s `updatePouchAttachment`/`attachToPouch`, built in M12 Task 5), the
  very next tick the joey's whole view is reparented into the mother's rig `pouch` container at a
  fixed local offset — also an instant snap, no eased transition, no "climbing in" motion of any
  kind. The sim design (real Creature, real position-follows-mother mechanism) is sound per M12's
  own review; the *transition* between "walking beside her" and "riding in the pouch" is simply
  unanimated, and that is exactly what reads as "magically."
- **Item 4, not yet root-caused — needs investigation, not a guess.** `feedMode: 'nurse' | 'carry'
  | 'self'` (M10) plus M12's contact-ring/facing/pacing work did differentiate feeding mechanically
  across those three buckets, and M12 gave four species (rabbit/deer/robin/kangaroo) new
  `feedGive`/`feedTake` poses. But the user's read after living with the deployed build is that it
  still feels like "one mechanism, tuned" rather than each species' actual real behavior. This
  needs the next session to actually watch multiple species feed side by side and identify
  specifically what reads as same-y (motion? pacing? the *kind* of feeding act being depicted vs.
  what that species really does?) before designing a fix — the M12 lesson (a mechanism can be
  correct and still not read right) applies here too.

## Decisions

None yet — deliberately left open. Per this project's working process, the next session should
run `superpowers:brainstorming` before writing any plan, the same way M12 did. In particular:
- Item 1 is close to mechanical (branch the brood/InspectCard text, and likely the sim-level
  gestation activity, on `reproduction.mode`) but the exact wording/UX for live-birth gestation
  ("expecting"? "close to giving birth"?) is a design call, not just a bugfix.
- Item 2's actual scope (verify-only vs. redesign) depends on watching item 1's fix live first.
- Item 3's fix approach (a genuine climb-in animation clip vs. a shorter eased position tween vs.
  something else) is a real design choice.
- Item 4 needs the investigation described above before any fix is scoped — this is likely the
  largest and least-defined item of the four, and should not be rushed into a plan without first
  understanding, per species, what "real life way" concretely means (as M12's brainstorm did for
  "recognizable" — silhouette/markings/shading/motion as four separately checkable things).

Related, not from this review but still open per CLAUDE.md: M13's other candidate item (apply the
M12 rig-art recipe to the remaining eight species) and the flagged pre-existing `'gather'` freeze
bug (~25% of population can permanently freeze, unrelated to this review's four items) — the next
session should decide how these all relate (one milestone or several) during its own brainstorm.
