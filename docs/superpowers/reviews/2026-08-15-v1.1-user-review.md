User feedback after the v1.1 live review (verbatim themes):

1. **Feeding kids not realistic** — parents should find food and feed them, or kids drink milk
   from the mother — "whatever applicable from the real-life creatures."
2. **Births/hatches not realistic** — kids "magically appear"; eggs should crack, babies should
   emerge per that creature's real behavior.
3. **Stuck creatures** — some stand motionless doing nothing, "like stuck."
4. **Rabbits on water** — land creatures seen moving on the pond.
5. **Text labels annoying** — replace with animation cues (e.g. drifting z·z·z for sleep).
6. **Click-to-inspect** — click a creature → who it is (father / mother / kid 1 / kid 2 …).
7. **Smoother, more animated** — closer to animated-video quality.
8. **More creatures** — delegated: "if you suggest."
9. **General improvements** — delegated.
Meta: optimize token cost; tier models per task (haiku/sonnet/opus) with Fable orchestrating.

## Root causes (from two code investigations)

- **Stuck (real bug):** socialize/court ring targets (behaviors.ts:207-211) are passed to
  moveToward with NO canOccupy validation — every other target generator clamps. If the ring
  point lands in water and dist ≤ speed, moveToward returns 0 ("arrived") WITHOUT moving
  (movement.ts:28-34); socialize never checks the return and never gets within relief range →
  motionless indefinitely. Likeliest near reed food spots where all species cluster.
- **Stuck (legible-but-legal):** nap is 20+ real seconds motionless by design; idle 3-8s;
  eating-in-place ~6s+. Part of the reports are correct behavior reading as stuck.
- **Water-walking (real bug):** advance()'s stranded-escape branch (movement.ts:69-79) moves
  full unchecked steps every tick — a stranded creature can genuinely traverse water for
  several ticks. Trigger unconfirmed; the ring bug above is the prime suspect entry point.
- **Water-walking (visual):** reed FOOD_SPOTS sit at pond ×1.10 and ALL species share the spot
  list — rabbits legally forage on the 1.0–1.18× feathered sand band, visually "on the water."
- **Labels:** `debugLabels = true` by default (Renderer.ts:248) — raw activity ids over every
  creature at T2 unless the user finds the backtick DevPanel. Family home labels separate
  (always on from T1, no toggle) — kept, they're part of the charm.
- **Feeding:** one fetch+carry flow for all species (family.ts:329-341, behaviors.ts:233-270).
- **Births:** eggs vanish the instant phase flips (homeLayer full redraw); babies spawn at
  home ± jitter with only a sparkle — no crack, no emergence.
- **Inspect infra exists:** DevPanel already tap-vs-drag discriminates and has
  Renderer.pickCreature (nearest within 80/zoom); Creature has sex + stage; Family.childIds is
  stable birth order; mother = parents.find(sex==='f') pattern (family.ts:251); familyName()
  exists (12-name list) — per-creature names need an id-hash generator.

## Decisions (controller, per user delegation)

- **New species (item 8):** squirrel (forest quadruped, live birth → showcases nursing),
  frog (pond amphibian, egg clutch, self-feeding tadpole-hatched young — real frogs don't
  provision), turtle (shore amphibian, sand-nest eggs, self-sufficient hatchlings, serene and
  near-silent — realistically so). No predators — gentle-realism holds.
- **Feeding realism (item 1):** species gain `reproduction.feedMode: 'nurse' | 'carry' | 'self'`
  — nurse: rabbit, deer, squirrel (mother nurses at home; babies gather to her); carry: robin,
  duck, owl, dodo, phoenix (fetch + carry to nest, as now); self: koi, frog, turtle (young
  filter-feed/forage; parents never provision — true to life).
- **Births (item 2):** render-staged (no sim change): hatch = shell cracks then halves fade
  while the chick scales in; live birth = kits emerge from the burrow mouth with a scale-in;
  eggs no longer pop out of existence.
- **Labels (item 5):** activity text OFF by default (DevPanel can re-enable); meaning carried
  by the glyph layer, now gently animated, + drifting z·z·z for sleepers.
- **Cost discipline (meta):** implementers/reviewers tiered haiku→sonnet→opus by task risk;
  opus only for sim-heavy work and the final review; Fable controls only.
